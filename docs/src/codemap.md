# Code map

Which functions of `src/` each feature of ProjectedSphericalHarmonics runs. On the left are the three kinds of
domain (the unit disk, `disk(M)`; an ellipse, `ellipse(a, b, M)`; and a domain mapped conformally from samples of its
boundary, `domain(γ, M)`), and below them the options: the basis and transforms, the Laplace operators, the volume
and differential operators, Stokes, shape derivatives, and suspensions of many bodies. Each option is marked with the
domains it applies to (D: disk, E: ellipse, C: conformal domain); every marked combination was checked by running
it, and the underlined mark is the domain the option is run with and compared with. Many options are for the disk
alone (the volume potentials, the derivatives, ``\Delta^{-1}``, the shape derivatives and ``\mathcal{S}\mathcal{N}^{-1}``
have methods for `Disk` only); `ellipse` does not build ``\mathcal{N}``; and the closed-form close evaluation between
nearby bodies applies to disks and ellipses, while a conformal domain always uses node quadrature.

Each setting is a small run, changed from the base case (`disk(16)`, a 17 × 33 grid, and one Laplace solve
`𝒮⁻¹(1, D)`) in that setting only, under line coverage, and the lines it executes are mapped back to the top-level
functions of `src/`. A function is a name in a file, with all its methods there; the Disk methods of `𝒮`, `𝒮⁻¹`,
`𝒩` and `𝒩⁻¹` are generated by the macro `@wrap_operator`, which stands for them in `operators/integral.jl` (the
functions named `𝒮`, `𝒩` and `𝒩⁻¹` there are the methods for a `Domain`). The three domains build their
discretization; the options start from the same three (at `M = 16`; the conformal domain a three-lobed shape from 128
boundary samples), built once before the runs. The suspension options move two bodies a quarter of a radius apart, so
that the close evaluation is used.

On the right is the package, by directory: `domains` (the disk, the ellipse and the conformal domain), `conformal`
(the conformal map and the shape derivatives), `spectral` (grids, eigenfunctions, transforms), `operators` (integral,
Stokes and differential operators), `solvers` (Poisson, GMRES), `suspensions` (many bodies: Ewald sums and close
evaluation) and `algorithms` (adaptive cross approximation). Click a directory to open it; each file has one dot per
function. A link joins a setting to every visible row in which it runs functions that the setting it is compared with
does not (a domain is compared with the base case, an option with its underlined domain); the wider the link, the
more functions. Hover over a domain to dim the options that do not apply to it, over any setting to see the functions
it runs, and over a dot to see the function's name, its docstring and the settings that run it.


The map shows only what these runs reach: each option is run with one domain, so the inverse hypersingular operator
of the disk (`laplace3d_hypersingular_inverse!`; `𝒩⁻¹` is run on the conformal domain) shows up as not run, and so
does `Ŵ`, which nothing in the package calls. It is regenerated by hand after a change to `src/`, so it may lag the
code; the date and commit of the run are under the map. To regenerate it (under a minute; from the package root):

```
julia --project=docs docs/codemap.jl
```

## Layout

| Path | |
|:--|:--|
| `src/ProjectedSphericalHarmonics.jl` | arithmetic on tuples of arrays (the vector fields `(u_x, u_y)`), includes, exports, and the FFTW threads fix in `__init__` |
| `src/domains/` | `disk.jl` (`Disk`, `disk`: the grid and the coefficient-space operators), `ellipse.jl` (`ellipse`, `EllipseGeometry`), `domain.jl` (`Domain`, `domain`: a conformally mapped domain from boundary samples) |
| `src/conformal/` | `conformal.jl` (`conformalmap`, from the boundary curve by a Cauchy integral), `shape_derivatives.jl` (`δ𝒮`, `δ𝒩`, `δ𝒱`, `δℬ`) |
| `src/spectral/` | `grids.jl` (`legpts`, `trigpts`, `diskpts`), `eigenfunctions.jl` (`ylm`, `∂ylm∂ζ`, `Nlm`, `λlm`, `Clmn`, `lm2index`, `index2lm`), `transforms.jl` (`psh`, `ipsh`, `psh!`, `ipsh!`, `upsample`, `psh_matrix`, `ipsh_matrix`), `recurrences.jl` (multiplication by the weight in coefficient space) |
| `src/operators/` | `matrices.jl` (the coefficient-space matrices of the single layer, Stokes and ``\mathcal{S}\mathcal{N}^{-1}``, `fourier_coeffs`), `integral.jl` (`𝒮`, `𝒮⁻¹`, `𝒩`, `𝒩⁻¹`, `𝒮𝒩⁻¹`, `𝒱`, `ℬ`, `𝒯`), `stokes.jl` (`𝒮_st`, `𝒮_st⁻¹`, `stokes_mobility_matrix`, `stokes_mobility_solve`), `differential.jl` (`∂ζ`, `∂ζ̄`, `∂n`, `∂x`, `∂y`, `grad`, `div`, `lap`), `operators.jl` (`trace`, `integral`, `apply`, `solve`) |
| `src/solvers/` | `solvers.jl` (`Δ⁻¹`, `gmres`) |
| `src/suspensions/` | `stokes.jl` (`suspension_mobility_solve`, `suspension_velocity_eval`, `suspension_velocity_solve`, `suspension_self_matrix`), `ewald.jl` (`StokesEwald`: Ewald + NUFFT), `close_eval.jl` (closed-form close evaluation between disks and ellipses) |
| `src/algorithms/` | `aca.jl` (`aca`, adaptive cross approximation) |
| `test/` | `runtests.jl`, `test_integral.jl`, `test_differential.jl` (with the Poisson solver), `test_domain.jl`, `test_stokes_mobility.jl`, `test_close_eval.jl` |
| `examples/` | the scripts of [Examples](@ref), with their own `Project.toml`: `eigenfunctions.jl`, `poisson.jl`, `concentration.jl`, `stokes.jl`, `ellipse.jl`, `microbial_droplet.jl` |
| `docs/` | this site: `make.jl`, `src/` (the pages), `figures/` (data and plots), `codemap.jl`; `stokes_mobility_fmm_solve.md` (notes on the frames of the suspension solve); `.github/workflows/Documentation.yml` builds it and publishes it to the gh-pages branch |
